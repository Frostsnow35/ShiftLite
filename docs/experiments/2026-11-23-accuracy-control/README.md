# 精度控制量化定档实验（#18，2026-11-23）

开题三(二)第三步唯一明文未决问题：「精度控制量化会损失多少加速收益，待 PoC 完成后实测定档」。
本实验用**同一校准集（trainA 前 300 张）**产出两版 INT8 并对照现行 PTQ。

## 产出模型

| 版本 | 模式 | 产物 |
|---|---|---|
| C（现行） | `ptq_mixed_skip_mvn` | `impl/artifacts/models/horse2zebra_int8.*` |
| C_ac（本实验） | `accuracy_control_skip_mvn` | `impl/artifacts/models/horse2zebra_int8_ac.*` |

NNCF 精度控制量化：初始度量 1.0 → 量化后 0.9955，绝对掉点 0.0045（< 0.01 门槛），
度量定义 `1/(1+MSE)`（对 FP32 参照输出，8 张校准图验证）。
**修复记录**：`core/quantize.py` 原 `validation_fn` 返回 `-MSE`，FP32 自比对时度量=0，
NNCF `calculate_accuracy_drop` 相对掉点除零崩溃（2026-11-23 实测）；已改为严格正值。

## 测速（§3.3 协议：预热 3 + 20 轮，均值±标准差；本机 i5-1340P，2026-11-23 会话）

| 模型 | 延迟 | FPS | 体积 |
|---|---:|---:|---:|
| OpenVINO FP32（f32 hint） | 846.5 ± 52.0 ms | 1.18 | 43.52 MB |
| C · PTQ INT8 | 269.0 ± 14.4 ms | 3.72 | 11.10 MB |
| C_ac · 精度控制 INT8 | 279.5 ± 24.4 ms | 3.58 | 11.10 MB |

- **C_ac 相对 C 慢约 4%**（269.0→279.5 ms），体积同为 11.10 MB。
- 本会话绝对值受沙箱负载影响（同机主表 C=202.6 ms 为 2026-10-26 独立会话），
  **只采用同会话 C vs C_ac 比值定档**，不与主表数字混排。

## 质量抽测（E3 口径：b=FP32 OV 输出 vs c=INT8，n=30 testA）

| 版本 | SSIM(b,c) | LPIPS(b,c) |
|---|---:|---:|
| C · PTQ | 0.8895 | 0.0944 |
| C_ac · 精度控制 | 0.8859 | 0.0982 |
| C vs C_ac 互比 | SSIM 0.8445 | — |

主表（n=120）SSIM(b,c)=0.8854、LPIPS(b,c)=0.099，与抽测同量级，抽样口径成立。

## 定档结论

**精度控制量化对 horse2zebra 生成任务无收益，维持 PTQ 作为 C 组。**

1. 加速损失约 4%（延迟 269.0→279.5 ms）；
2. 质量未见改善：SSIM 0.8895→0.8859、LPIPS 0.0944→0.0982，均略差（差异在 n=30 抽测噪声内）；
3. 两版 INT8 确为不同模型（互比 SSIM 0.8445），非同一产物；
4. 开题「收益是否以不可接受的质量变化为代价」的另一半答案：PTQ（skip MVN）质量代价可接受
   （SSIM 0.89 / LPIPS 0.094 量级），且换得 3–4× 延迟收益，无需精度控制档兜底。

边界：单机单会话、n=30 抽测、C_ac 的 NNCF 验证集为校准集内 8 张（trainA 域）；
结论按本口径成立，不外推到其他 pair/网络。

产物：`bench.json`、`quality_sample.json`（本目录）；脚本逻辑见 `impl/core/quantize.py --accuracy-control`。
