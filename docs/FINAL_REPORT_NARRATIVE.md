## 一、定位口径（回答“应用范围太窄”）

题目是「实例对象图像迁移应用」。horse2zebra 是**先行收口的保底实例**，项目主角是**可配置迁移引擎 + 量化加速 + 层间分工分析**。

- 应用范围由**引擎与配置面**决定，不由单个 pair 决定：`pairs/*.json` 换权重/域映射即换任务（#24）。
- 多对演示只证明**系统兼容多种任务**，**不证明单个模型具备通用迁移能力**。
- 不把 AdaIN 支线（#32）与 CycleGAN 主线放同一张指标表：前者是“换画风”，后者是“换实例外观”，任务不同。

## 三、层间分工跨类型结论（#19）

- horse2zebra：残差块余弦 **0.9994→0.9644** 单调下降，最大漂移 `resblock_09`；浅层 `down_relu` ≈0.9996 几乎不动。
- zebra2horse：**0.9995→0.9649**，最大漂移仍在 `resblock_09`，与正向几乎重合。
- 判读：浅层对应结构/位置，深层对应风格/纹理；LPIPS 退化与深层漂移同向，结构指标保持较高 → **风格信息比结构信息更易被数值扰动**。属关联证据，非因果证明。
- 方向不变性说明该分工主要与**架构+量化**有关，与迁移方向无关。

## 四、汇报视频分镜（建议 3–4 分钟）

1. **开场（30s）**：上传一张马图 → 选 horse2zebra → 出斑马图；一句话点题“能出图之外，还要能快部署”。
2. **切换迁移对（30s）**：下拉切到 zebra2horse，现场出图 → “换对象/换域=换配置”。
3. **三组对照（60s）**：A/B/C 同图出图 + 延迟/体积数字（i5 主表）；强调“结论只来自实测，不预设 INT8 更快”。
4. **质量与层间（60s）**：LPIPS/IoU/Canny + 层漂移曲线；说明“风格先掉、结构更稳”。
5. **边界（30s）**：多对只证明系统兼容；AdaIN 是支线不混表；数据未就绪的 pair 不演示。

## 五、答辩 Q&A 预案

| 问题 | 回答要点 |
|---|---|
| 为什么原来只做马换斑马？ | 保底先行收口；引擎化扩展已验证 horse2zebra/zebra2horse；多对=换配置，不证明单模型通用。 |
| 为什么不直接上 CUT/StarGAN/扩散？ | 选型依据见 `docs/技术调研_图像迁移技术对比.md`；换引擎会使量化与层间分析的“同权重、只变精度”口径失效。 |
| 为什么不用 MicroAST/Hist2Style？ | 权重可得性/任务不同（#32）：MicroAST 未放推理权重；Hist2Style 只做调色。 |
| INT8 掉点可接受吗？ | LPIPS(b,c)=0.099、Canny=0.620、掩码 IoU=0.814；质量变化可测但结构保持，结论按实测报告，不预设。 |
| 层间分工是不是过度解读？ | 是表示相似度的关联证据，不是因果；已写明边界与方向不变性旁证。 |
| 多对结果能说明通用吗？ | 不能。只说明系统兼容；每对独立训练。 |
