## 3. 技术路线（课程阶段③：设计技术方案）

### 3.1 基线方法
- **CycleGAN**（Zhu et al., ICCV 2017）：无配对双向生成，ResNet 生成器 + PatchGAN 判别器 + 循环一致性损失（cycle consistency）+ identity loss。
- 训练（加分项，定位 = 流程验证）：Colab / Kaggle 免费 T4 训练数个 epoch 仅证明训练流程可执行，**不作为生成质量的证据**。从头完整训练放在核心任务完成之后；若正式研究训练，报告 FID/KID 随 epoch 的变化曲线，而非只报告"训练能启动"。
- 推理：本地加载官方预训练 `latest_net_G.pth`，单图前向出图。

### 3.2 PoC（第一优先级，先于一切开发）
- 目标：验证"PyTorch CycleGAN 生成器 → OpenVINO 转换 → INT8 量化"整条链路在本机可通。Demo、指标、多迁移对全部排在其后。
- 步骤：官方仓库脚本下载预训练模型（`./scripts/download_cyclegan_model.sh horse2zebra.pth`，伯克利直链留作文档备份）→ 转换 → 同一张输入图分别跑 PyTorch 与 OpenVINO → 检查输出图像正常、数值差异合理（逐像素绝对误差量级记录在案）→ 转换后模型成功保存、重新加载、再次推理。
- 通过标准：完成至少一次转换 + 推理 + 输出对比，并记录两种运行方式的耗时。INT8 遇阻时先解决 horse2zebra 最小样例，通过前不扩展迁移对、不写 Demo。

### 3.3 小改进（核心差异化，扣 AI-infra 推理优化）
- 转换链路：**PyTorch → ONNX → OpenVINO IR**（输入固定 1×3×256×256，不做动态轴）。opset 选择与算子兼容性由 PoC 实测定档并记录；生成器算子（ReflectionPad2d / InstanceNorm）的兼容性列为 PoC 首查项。
- 用 **NNCF PTQ（Post-Training Quantization）做 INT8 量化**：校准集 = horse2zebra testA 前 100 张；量化对象仅生成器。
- 推理硬件：**OpenVINO CPU 插件为准**（Intel Core i5-1340P）。CPU 上的 FP32 / INT8 实验完整后，才决定是否测 Iris Xe 集成显卡。
- 三组对比（结论只从三组得，不预设 INT8 更快）：**A = PyTorch FP32（基线）；B = OpenVINO FP32（隔离运行时收益）；C = OpenVINO INT8（量化增量收益与质量损失）**。测速协议：三组同输入图、同分辨率 256×256、batch size = 1、同一台设备；计时前预热；每组 ≥ 5 轮，报告延迟分布（均值 ± 标准差）与吞吐 FPS，不取单次时间。
- INT8 质量不可接受时的备选链（有序）：
  1. **OpenVINO FP32 保底**——迁移功能与 A/B/C 实验完整性不受影响（B 组本来就要跑）；
  2. **NNCF 精度控制量化**（`nncf.quantize_with_accuracy_control`）——需校准数据 + 验证数据 + 评价函数，以部分加速收益换质量；
  3. **FP16 不作为 CPU 提速手段**（i5-1340P 无 AVX512-FP16，CPU 上 FP16 不加速、只省约一半体积），仅作为 Iris Xe GPU 上的对照组。
- 模型下载双源：主源官方仓库下载脚本，备源 HuggingFace 镜像（下载失败时另寻可用镜像仓库）。

### 3.4 Demo
- 本地 Web（Gradio 或 Streamlit）：上传图 → 选迁移对 → 出图；录制 Demo 视频。Demo 在 PoC 通过后开发。

## 4. 评价指标（课程硬性要求，无 ground truth 必须有对策）

| 维度 | 指标 | 说明 |
|---|---|---|
| 量化保真度（问题①：量化是否改变生成结果） | **LPIPS 三对：LPIPS(a,b)、LPIPS(b,c)、LPIPS(a,c)** | 记号：a = PyTorch FP32 输出，b = OV FP32 输出，c = OV INT8 输出（同一张输入马图各自生成）。三对各答一个归因问题——LPIPS(a,b) = 运行时转换差异（预期 ≈ 0，偏大即转换有 bug）；LPIPS(b,c) = 量化本身引入的差异（核心）；LPIPS(a,c) = 原版到终版总差异（≈ 前两项之和）。逐图计算后取 test set 均值，异常图单独登记 |
| 迁移质量（问题②：生成结果是否接近真实斑马域） | FID、KID | 两批生成结果（FP32 批、INT8 批）分别与**同一批**真实斑马 test 图比较特征分布；评估集 = 完整 test set（约 100–120 张），FID 在 <100 样本上无统计意义，KID 对小样本稳健，两者并列报告。注意：衡量的是与真实域的分布距离，不直接等于"逼真度" |
| 结构保真（问题③：对象姿态 / 轮廓 / 背景是否合理保留） | 前景掩码 IoU、背景区 SSIM、边缘图 SSIM，逐图记录 | 三项各管一处：① **轮廓/位置**——torchvision Mask R-CNN（`maskrcnn_resnet50_fpn_v2`，COCO 91 类完整类表，含 horse 与 zebra；零训练）分别对输入马图与生成斑马图提取实例掩码（按类名读索引），算 IoU/Dice；若生成图被改出畸形动物，掩码检出会失败，IoU 直接塌陷，可按图定位。注意 torchvision 的语义分割模型（DeepLabV3 等）类表仅 VOC 21 类、无 zebra，不可用；② **背景**——掩码外区域算 SSIM，验证背景未被生成器改写；③ **姿态**——Canny 边缘图算 SSIM 作客观参考（跨域纹理变化大，像素级 SSIM 会被纹理差异污染，边缘图只比结构）。任一项异常的样本单独登记归档 |
| 任务型（补充解释：生成图是否含斑马域可识别特征） | 斑马判别准确率 | ImageNet 预训练 ResNet-50（torchvision），按类名 "zebra" 从类别表读索引，对生成图的判别率；不能独立证明逼真 |
| 主观（兜底） | 人工打分问卷 | 统一问卷四项：视觉自然度 / 斑马特征 / 姿态与结构保留 / 背景保留，固定评分标准；比较 FP32 vs INT8 组；异常样本（畸形动物、背景被改写、姿态崩坏）逐图标注归类 |

性能指标：单图延迟(ms)、吞吐(FPS)、模型体积(MB)、内存占用，按 §3.3 测速协议在 A/B/C 三组上采集。

## 10. 创新点表述（避免"纯复现"）

不做单纯 CycleGAN 复现，而是把项目定位为**"通用实例迁移方法 + 面向 Intel 硬件的推理加速落地"**：把风格迁移从"能出图"推进到"能快部署、低延迟"，既差异化，又扣成员 AI-infra 推理优化方向。证据链 = A/B/C 三组归因实验（运行时收益与量化收益分离）+ 双类质量指标（量化保真度与迁移质量分离），结论只来自实测，不预设 INT8 更快。
