## 3. 技术路线（课程阶段③：设计技术方案）

### 3.1 基线方法
- **CycleGAN**（Zhu et al., ICCV 2017）：无配对双向生成，ResNet 生成器 + PatchGAN 判别器 + 循环一致性损失（cycle consistency）+ identity loss。
- 训练（**正式环节·第六步**）：Colab / Kaggle 免费 T4 小规模训练 horse2zebra，把三类损失（对抗、循环一致性、恒等）落到实处。验收口径：记录生成器/判别器/循环一致性损失随 epoch 变化 + FID、KID 随 epoch 下降曲线；收敛后与官方权重在同一测试集对比并如实报告差距。
- **与主对照链严格隔离**：自训权重不进 A/B/C 三组，因其引入训练超参、轮数、数据划分等新变量，会破坏"同源权重、只变精度"这条干净对照。主对照答"运行环境和数值精度的影响"，训练复现答"我们能否复现这套方法"，两问题独立、不同表混用。
- 推理：本地加载官方预训练 `latest_net_G.pth`，单图前向出图。

### 3.2 PoC（第一优先级，先于一切开发）
- 目标：验证"PyTorch CycleGAN 生成器 → OpenVINO 转换 → INT8 量化"整条链路在本机可通。Demo、指标、层间分析全部排在其后。
- 步骤：官方仓库脚本下载预训练模型（`./scripts/download_cyclegan_model.sh horse2zebra.pth`，伯克利直链留作文档备份）→ 转换 → 同一张输入图分别跑 PyTorch 与 OpenVINO → 检查输出图像正常、数值差异合理（输出映射到 0–255 灰度后逐像素比对；预设可忽略阈值 = 平均绝对误差 ≤ 0.5 个灰度级、最大绝对误差 ≤ 5 个灰度级，PoC 时按实测校准并记录）→ 转换后模型成功保存、重新加载、再次推理。
- 通过标准：完成至少一次转换 + 推理 + 输出对比，并记录两种运行方式的耗时。INT8 遇阻时先解决 horse2zebra 最小样例，通过前不写 Demo。

### 3.3 量化加速与可控扰动对照（工程增量）
- 转换链路：**PyTorch → OpenVINO IR 直转**（`ov.convert_model` + `ov.save_model`，输入固定 1×3×256×256，不做动态轴，不产生 ONNX 等中间格式）。转换由示例输入驱动追踪，算子兼容性由 PoC 实测定档并记录；生成器算子（ReflectionPad2d / InstanceNorm）的兼容性列为 PoC 首查项。
- 用 **NNCF PTQ（Post-Training Quantization）做 INT8 量化**：校准集 = horse2zebra trainA 前 300 张（NNCF 默认子集规模；训练图，与评测所用 test 集隔离）；量化对象仅生成器。
- 推理硬件：**OpenVINO CPU 插件为准**（Intel Core i5-1340P）。CPU 上的 FP32 / INT8 实验完整后，才决定是否测 Iris Xe 集成显卡。
- 三组对比（结论只从三组得，不预设 INT8 更快）：**A = PyTorch FP32（基线）；B = OpenVINO FP32（隔离运行时收益）；C = OpenVINO INT8（量化增量收益与质量损失）**。测速协议：三组同输入图、同分辨率 256×256、batch size = 1、同一台设备；计时前预热；每组 ≥ 5 轮，报告延迟分布（均值 ± 标准差）与吞吐 FPS，不取单次时间。
- A/B/C 三组同源权重（A/B 同权重，C 为同一套权重的确定性量化版本）、只变运行环境与数值精度，构成干净控制对照——既是加速收益的量化口径，也是层间分析的可控扰动源。
- INT8 质量不可接受时的备选链（有序）：
  1. **OpenVINO FP32 保底**——迁移功能与 A/B/C 实验完整性不受影响（B 组本来就要跑）；
  2. **NNCF 精度控制量化**（`nncf.quantize_with_accuracy_control`）——需校准数据 + 验证数据 + 评价函数，以部分加速收益换质量；
  3. **FP16 不作为 CPU 提速手段**（i5-1340P 无 AVX512-FP16，CPU 上 FP16 不加速、只省约一半体积），仅作为 Iris Xe GPU 上的对照组。
- 模型下载双源：主源官方仓库下载脚本，备源 HuggingFace 镜像（下载失败时另寻可用镜像仓库）。

## 4. 评价指标（课程硬性要求，无 ground truth 必须有对策）

| 维度 | 指标 | 说明 |
|---|---|---|
| 量化保真度（量化是否改变生成结果） | **LPIPS 三对：LPIPS(a,b)、LPIPS(b,c)、LPIPS(a,c)** | 记号：a = PyTorch FP32 输出，b = OV FP32 输出，c = OV INT8 输出（同一张输入马图各自生成）。LPIPS(a,b) = 运行时转换差异（预期 ≈ 0，偏大即转换有 bug）；LPIPS(b,c) = 量化本身引入的差异（核心）；LPIPS(a,c) = 原版到终版总差异。逐图计算后取 test set 均值，异常图单独登记 |
| 迁移质量（生成结果是否接近真实斑马域） | FID、KID | 两批生成结果（FP32 批、INT8 批）分别与同一批真实斑马图比较特征分布；生成批 = testA 全部 120 张马图各自的输出，真实参考批 = testB 全部 140 张斑马图。FID 在百张量级样本上估计波动较大，KID 对小样本稳健，两者并列报告 |
| 结构保真（对象姿态 / 轮廓 / 背景是否合理保留） | 前景掩码 IoU、背景区 SSIM、边缘图 SSIM，逐图记录 | ① **轮廓/位置**——torchvision Mask R-CNN（`maskrcnn_resnet50_fpn_v2`，COCO 91 类完整类表，含 horse 与 zebra；零训练）对输入马图与生成斑马图提取实例掩码（按类名读索引），算 IoU/Dice；② **背景**——掩码外区域算 SSIM，验证背景未被改写；③ **姿态**——Canny 边缘图算 SSIM 作客观参考。任一项异常样本单独登记 |
| 任务型（补充：生成图是否含斑马域可识别特征） | 斑马判别准确率 | ImageNet 预训练 ResNet-50（torchvision），按类名 "zebra" 从类别表读索引，对生成图的判别率 |
| 主观（兜底） | 人工打分问卷 | 统一问卷四项：视觉自然度 / 斑马特征 / 姿态与结构保留 / 背景保留，固定评分标准；比较 FP32 vs INT8 组；异常样本（畸形动物、背景被改写、姿态崩坏）逐图标注归类 |

性能指标：单图延迟(ms)、吞吐(FPS)、模型体积(MB)、内存占用，按 §3.3 测速协议在 A/B/C 三组上采集。

## 5. 文献综述（课程阶段②）

- **CycleGAN**（Zhu et al., 2017, ICCV）— 核心方法
- **pix2pix**（Isola et al., 2017, CVPR）— 成对对照，理解"配对 vs 无配对"差异
- **Neural Style Transfer**（Gatys et al., 2016, CVPR）— 风格迁移背景
- **Unpaired Image-to-Image Translation**（背景与对比）
- **OpenVINO / INT8 量化**相关文档 — 支撑转换与量化加速手段的落地
- **Yosinski et al., 2014（NIPS）** — 层间分工的早期证据：浅层特征通用，越靠输出越依赖任务
- **Bau et al., 2017（CVPR，Network Dissection）** — 用语义概念集度量中间层单元与概念的对齐
- **Bau et al., 2019（ICLR，GAN Dissection）** — 同一思路用于生成器：对象对应单元集中在中段，浅层偏几何布局、深层偏纹理边缘

## 10. 创新点表述（避免"纯复现"或"纯部署报告"）

项目交付一个**可用的实例对象迁移应用并做量化加速**（工程价值），同时给出**网络层间分工分析**（深度）——不做单纯 CycleGAN 复现，也不做成只有部署指标的工程报告。

- **应用与加速（工程）**：可运行 Web Demo + PyTorch → OV IR 直转 + INT8 量化加速，A/B/C 给出可量化的延迟/吞吐/体积收益。
- **探针（方法支点）**：A/B/C 三组同源权重、只变运行环境与数值精度，构成干净控制对照——既是加速收益的量化口径，也是层间分析的可控扰动源。
- **层间分工（深度）**：中间层逐层漂移对齐，回答哪一层对数值表达敏感、它承载的是风格还是结构信息——让工程交付带上可讲清的深度，直接回应指南"研究深度神经网络的图像表示中与图像风格相关的特点"。
- **落点**：工程侧给出可量化的部署收益，深度侧给出层间分工结论；即便层间分工结论不成立，这套探针流程与对照设计作为负结果同样可如实报道。
